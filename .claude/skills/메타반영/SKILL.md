# 결과 문구 엑셀 → 코드 반영

기획자가 작성한 엑셀의 문구를 `web/src/phrases.js`에 반영하고, 배포 파일까지 새로 만든다.
**사용자는 개발자가 아닐 수 있다.** 명령어를 늘어놓지 말고, 알아서 실행한 뒤 결과만 쉬운 말로 알려줄 것.

## 순서

### 1. 엑셀 위치 확인

기본 경로는 `docs/용신_결과문구_작성양식.xlsx`.
사용자가 다른 파일(다운로드 폴더 등)을 언급하거나 첨부했다면 그 경로를 쓴다.
경로가 애매하면 추측하지 말고 어느 파일인지 한 번 묻는다.

### 2. 반영 실행

```bash
python3 tools/apply-phrases.py [엑셀경로]
```

- 안 채워진 칸이 있으면 **아무것도 쓰지 않고** 어느 시트 몇 번 칸이 비었는지 알려준다.
  그대로 사용자에게 전달하고 여기서 멈춘다. 빈 칸을 임의로 채우지 말 것.
- `⚠` 경고(예: 예시 문구 그대로, E 시트 일부만 작성)는 반영은 되지만 반드시 사용자에게 전달한다.

### 3. 배포 파일 다시 만들기

```bash
cd web && npm run build
```

`web/dist/index.html` 한 파일이 실제 배포물이다.

### 4. 실제로 바뀌었는지 확인

프리뷰를 띄우고 회귀 케이스로 눈으로 확인한다.

- 프리뷰: `.claude/launch.json`의 `bujeokjip` (preview_start) → `http://localhost:8017/web/dist/`
- 확인 입력: **1979년 2월 2일 16시 45분 · 서울**
- 기대: 사주팔자 `무오 을축 경자 갑신`, 용신 한자 `火`
- 결과 화면에 새 문구가 나오는지, 용신 설명 영역(있다면)이 보이는지 확인
- 콘솔 에러가 없어야 한다

### 5. 보고

바뀐 문구를 **before → after로 요약**해서 보여준다. 전체를 다 붙여넣지 말고 달라진 것만.
커밋·푸시는 사용자가 요청할 때만 한다.

## 알아둘 것

- `web/src/phrases.js`는 **자동 생성 파일**이다. 직접 고치지 말 것 — 다음 반영 때 덮어써진다.
  문구를 바꾸려면 엑셀을 고치고 이 명령을 다시 돌린다.
- 문구 안의 `{용신}` `{기신}` `{희신}` 은 사람마다 다른 오행 이름으로 자동 치환되는 변수다. 그대로 둔다.
- 조후(C) 블록은 사주가 춥거나 더운 사람에게만 나간다. 평범한 사람은 이 문장이 빠진 채 조립되므로,
  C 없이도 말이 되는지 확인 대상이다.
- 용신 설명(E 시트)이 비어 있으면 그 영역은 화면에 안 나온다. 오류가 아니다.
- 엑셀 자체를 고쳐달라는 요청이면 이 명령이 아니라 `docs/용신_결과문구_작성양식.xlsx`를 직접 편집한다.
