# 로컬 테스트 서버 띄우기

기획자가 지금 코드 상태의 화면을 자기 브라우저에서 눌러볼 수 있게 만든다.
**사용자는 개발자가 아니다.** 명령어를 나열하지 말고 알아서 끝낸 뒤, 열린 주소 한 줄만 알려줄 것.

## 순서

### 1. 배포 파일 새로 만들기

```bash
cd web && npm run build
```

`web/dist/index.html` 한 파일이 화면 전체다. 이걸 새로 만들어야 최근 수정이 반영된다.

- `esbuild` 가 없다는 오류가 나면 `cd web && npm install` 을 먼저 한 번 돌리고 다시 빌드한다.
- 빌드가 실패하면 **서버를 띄우지 말고** 멈춘 뒤, 오류를 쉬운 말로 설명한다.
  (옛날 화면이 그대로 떠서 "반영됐다"고 착각하는 게 제일 나쁘다.)

### 2. 이미 떠 있는 서버 정리

포트는 **8017** 고정이다.

```bash
lsof -nP -iTCP:8017 -sTCP:LISTEN
```

- 우리 서버(`node … serve.mjs`)가 떠 있으면 그 PID만 `kill` 한다.
- **다른 프로그램이 8017을 쓰고 있으면 죽이지 말고 사용자에게 알린다.** 남의 프로세스를 임의로 끄지 말 것.
- 아무것도 없으면 그냥 다음으로.

### 3. 서버 켜기

Claude Code를 꺼도 계속 떠 있어야 하므로 세션에서 분리해 실행한다.

```bash
cd /Users/nhn/Documents/용신 && nohup node web/serve.mjs > /tmp/bujeokjip-server.log 2>&1 & echo started $!
```

띄운 뒤 응답이 올 때까지 잠깐 기다린다(최대 10초쯤). 확인:

```bash
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8017/
```

`200` 이 아니면 `/tmp/bujeokjip-server.log` 를 보고 원인을 알린다.

### 4. 기본 브라우저로 열기

```bash
open http://localhost:8017
```

`/` 로 들어가면 `web/dist/` 가 뜬다(서버가 알아서 연결해 둠).

### 5. 보고

이렇게만 알려준다.

- 열린 주소: **http://localhost:8017**
- 방금 빌드해서 지금 코드 상태가 반영돼 있다는 것
- 화면을 고친 뒤 다시 보려면 이 명령(`서버실행`)을 한 번 더 돌리면 된다는 것
- 서버는 계속 떠 있으니 브라우저만 새로고침해도 되지만, **코드를 고쳤으면 새로고침만으로는 안 바뀐다**(빌드가 필요하므로 이 명령을 다시 실행)

## 알아둘 것

- 브라우저에서 화면이 안 바뀌면 십중팔구 **빌드를 안 한 것**이다. 이 명령은 항상 빌드부터 한다.
- 그래도 옛날 화면이면 브라우저 강력 새로고침(맥: `Cmd + Shift + R`)을 안내한다.
- 서버를 끄고 싶다면: `lsof -ti tcp:8017 | xargs kill`
- 문구를 바꾸러 온 거라면 이 명령이 아니라 `메타반영` 이다. `메타반영` 은 문구 반영 + 빌드까지 하므로,
  그 뒤에 화면을 보고 싶을 때 이 명령을 이어서 쓰면 된다.
- 인터넷이 끊겨 있어도 동작한다(폰트만 시스템 글꼴로 대체됨). 계산은 전부 브라우저 안에서 한다.
